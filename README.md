## Pinned Transmission

<div align="center">

<img src="https://raw.githubusercontent.com/webneco/webneco/main/careflow.svg?v=3" width="100%" alt="CareFlow CMS — the visit loop" />

</div>

<br/>

**[CareFlow CMS](https://careflowcms.tech)** is a **multi-tenant clinic operating system** for solo doctors and multi-doctor clinics in India — mobile-first, installable as a PWA, WhatsApp-native from the first booking to the follow-up nudge.

The whole product collapses into one click. When a doctor taps **Confirm visit**, a single API transaction fires:

- 🧾 sequential **invoice** created (`INV-{year}-{seq}`, PDF rendered on demand — never stored stale)
- ✅ appointment marked **COMPLETED**
- 🔁 **follow-up** scheduled from the next-checkup date
- ⭐ **review request** queued behind a rating gate (≥ 4★ → Google, below → private feedback)
- 💬 **WhatsApp** summary sent to the patient

Everything downstream is fire-and-forget, so a slow WhatsApp API never blocks the doctor's screen.

<details>
<summary><b>🔬 &nbsp;Open the module manifest — all 9 subsystems</b></summary>

<br/>

| Module | What clinics get |
|:-------|:-----------------|
| 👤 **Patients** | Registration, `CF-` codes, history, allergies, tags, bulk import |
| 📅 **Appointments** | Booking, reschedule, check-in, slot conflict checks, digital consent |
| 🩺 **Consultations** | Vitals, diagnosis, treatment plan, prescriptions, billing line items |
| 🧾 **Billing & Invoices** | Per-clinic sequential numbering, on-demand PDF, payment status |
| 💬 **Engagement** | WhatsApp Cloud API, templates, delivery receipts, two-way inbox |
| ⭐ **Reviews** | Public rating gate that protects the clinic's public score |
| 🔁 **Follow-ups** | Recall rules + daily cron nudges, capped per patient |
| 📣 **Marketing** | Campaigns, audiences, referrals, consent + monthly send caps |
| 📊 **Dashboard & Reports** | Today's queue, revenue trends, funnels |

**Multi-tenant by design** — every row carries a `clinicId`, every API route resolves the session first. There is no cross-clinic query path.

</details>

<details>
<summary><b>⚙️ &nbsp;Open the engineering log — how it's actually wired</b></summary>

<br/>

- **Atomic confirm** — `POST /api/consultations/[appointmentId]/confirm` is the spine. Invoice, recall, review request and WhatsApp send all hang off that one transaction, fire-and-forget so a slow Meta API never blocks the UI.
- **PDFs are never stored** — `@react-pdf/renderer` renders on every request, so the document always matches current payment status.
- **Two WhatsApp paths** — `SIMPLE` mode turns a campaign into an assisted queue (staff tap, WhatsApp opens prefilled); `BUSINESS_API` dispatches in batches of 50 with scheduling.
- **The review gate is the clever bit** — ratings ≥ 4★ redirect to the clinic's real Google link; anything lower stays inside CareFlow as private feedback. The clinic's public score is protected by construction.
- **Tenancy is structural, not a filter** — `requireSession()` resolves the clinic, and every Prisma query is scoped by `clinicId`. There is no code path that can read across clinics.

</details>
